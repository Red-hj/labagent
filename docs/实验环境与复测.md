# OSPF 实验环境与复测

本项目没有安装或控制网络仿真软件。这里提供可供现有华为 VRP 实验环境使用的配置参考，设备型号、接口名称及导入方式须与实际环境对应。配置尚未在真实设备上验证。

## 实验拓扑

```text
PC1 ── R1 GE0/0/2    R1 GE0/0/0 ── R2 GE0/0/0    R2 GE0/0/2 ── PC2
```

| 节点或接口 | 地址 | 网关 |
| --- | --- | --- |
| PC1 | 192.168.10.10/24 | 192.168.10.1 |
| R1 GE0/0/2 | 192.168.10.1/24 | 无 |
| R1 GE0/0/0 | 10.12.0.1/24 | 无 |
| R2 GE0/0/0 | 10.12.0.2/24 | 无 |
| R2 GE0/0/2 | 192.168.20.1/24 | 无 |
| PC2 | 192.168.20.10/24 | 192.168.20.1 |

正常配置位于 `data/lab/R1_correct.cfg` 和 `R2_correct.cfg`。故障参考是 `R2_area_fault.cfg`，其中 R2 被配置到 Area 1，实验要求 Area 0。配置应在已有的可控实验环境中使用。

区域不匹配时，直连接口间仍可能正常 Ping。演示应检查 OSPF 邻居、远端路由和 PC1 到 PC2 的通信，而不能声称直连接口 Ping 必然失败。

## 采集运行结果

在配置修改生效并等待协议收敛后，按实际设备命令采集：

```text
display ospf peer
display ip routing-table
```

在 PC1 上 Ping 192.168.20.10。记录收发包数量。保留命令输出原文用于比赛证据；当前程序不会自动解析命令原文，需要按下面结构填写。此双端互联实验预期邻居为 Full，共享广播网的多设备场景需另行设计验证规则。

```json
{
  "neighbors": [{"link_id": "r1-r2", "state": "Full"}],
  "pings": [{
    "source": "PC1",
    "target": "192.168.20.10",
    "sent": 5,
    "received": 5
  }]
}
```

数据仅为格式示例，请填写真实结果。网页内勾选“针对当前配置新采集”，点击“绑定当前配置指纹”，再提交复测。

通过 API 复测时，先向 `/api/fingerprint` 发送当前诊断输入，取得 `config_fingerprint`，放入 `observations` 后提交诊断。指纹由配置、拓扑和实验要求共同生成；修改其中任何一项，旧观测就不能用于通过本次验证。

该机制不验证观测真实性。页面明确标记为用户提交的观测，不宣称本地程序执行了设备命令。
