# LabAgent 三分钟演示

## B 组实测：OSPF 区域错误与修复

在首页的示例下拉框选择“B 组实测：OSPF 区域错误与修复”，点击“带入实际运行对照”。右侧立即核对 `PC1 — R1 — R2 — PC2` 的两阶段记录，无需先调用模型。

1. 看故障卡：R2 互联接口为 Area 1，双向端到端 Ping 都是 1 发 0 收，双方没有 Full 邻居或远端 OSPF 路由。展开检查依据，可看到网关返回 `Destination Net Unreachable`，而 R1 到 R2 的直连 Ping 仍然 5 发 5 收。
2. 展开“查看配置改动”：恢复 R2 互联接口到 Area 0，LAN 配置没有变化。修复后两个方向的远端路由都由 OSPF 安装，邻接为 Full，两个端到端测试都恢复到 5 发 5 收。
3. 有模型时可点击“开始诊断”，让 Agent 解释差别并保存报告。首页比较与来源使用 [脱敏现场记录](../../data/examples/frr_lab02_area.json)，来自 2026-11-12 的 Alpine / WSL2 / FRRouting 10.2.2 实验。直连 Ping 是对照项；此结果不是华为 VRP 的设备记录。

## v0.13实验回放：找到未生效的命令

首页示例选择“实验回放：找到未生效的命令”，带入配套日志和15秒合成录屏。直接体验时间线时使用配套日志；展示视频文字识别时，先开始新的排查，再上传`data/examples/实验操作回放.webm`，等待实际识别进度。

1. 展示“11步操作、1处报错”和00:03关键操作：R2在接口视图输入network，随后出现终端报错。
2. 点击“查看这个时间点”，视频跳到00:03，画面与命令对应；展开操作时间线查看后续进入OSPF区域视图的过程。
3. 点击“分析这一步”，模型读取操作时间线、当前配置和Ping记录，解释为何后续只发布互联地址而遗漏Loopback目标，并给出具体继续步骤。
4. 追问原理、保存报告，再刷新页面展示录屏、材料、时间线和交流恢复。

讲解重点：终端操作回溯将设备、实际视图、命令结果与后续修改连起来；视频提供可定位的画面依据。OCR时间是文字在0.5秒采样画面中首次出现的时刻。正式展示采用当次运行输出，真实学生材料验证沿用相同入口。

## v0.12比赛主线：实验目标与主动检查

首页展开示例，选择“OSPF：连通性与实验目标”。用户提供同一实验的三阶段材料，诊断与目标检查实时运行。

| 阶段 | 操作 | 展示的机制 |
| --- | --- | --- |
| 目标不可达 | 载入①并开始诊断 | 从说明提取Ping、OSPF路由来源、配置要求；查看“下一步检查”，展开候选检查和各原因下的预期结果。程序按可区分原因对数与采集成本选择一项，所选项进入材料补充区。 |
| 静态路由使Ping成功 | 载入②，点击“核对修改结果” | 连通性通过，OSPF来源与配置要求仍失败；系统继续围绕这两项给出修改建议。展示目标要求和运行结果各自对应的原文。 |
| 通过OSPF完成 | 载入③，再核对修改结果 | 三项目标全部通过，同一会话结束排查，导出报告包含目标逐项核对与修改过程。 |

讲解重点：实验目标检查与检查选择由自己的工具实现，模型负责提出解释和候选检查。下面保留DHCP示例作为另一类材料的交互展示。实测记录与耗时见`docs/后续开发.md`，正式录屏按当次实际输出讲解。

## DHCP材料交互演示

当前演示使用项目自带的合成网络材料，诊断、检索和复测核对由已配置的模型与工具执行。浏览器打开首页，先确认“服务已就绪”，展开“用示例体验一次完整排查”。录屏前试跑一次，以实际响应时间安排停顿。

| 时间 | 页面操作 | 讲解重点 |
| --- | --- | --- |
| 0:00–0:25 | 点击“① 带入故障材料”，展开文件内容，再点击“开始诊断” | 学生提交配置、终端信息和实验现象；系统按材料开始排查。示例是PC1取得DHCP地址后无法跨网段访问服务器。 |
| 0:25–1:05 | 查看诊断说明，展开“查看材料依据”，点击“定位原文” | 地址池下发的网关与实验要求、R1接口地址不一致。每个判断可以回到上传材料的对应行，方便学生核对原因。 |
| 1:05–1:35 | 点击“给我修改步骤”；等候时展开“本轮工具记录”和“参考资料” | 模型选择读取材料、检索知识、比较材料和核对测试等工具。资料保留来源、版本和行号，工具记录来自本轮实际调用。 |
| 1:35–2:15 | 点击“② 带入修改与复测材料”，再点击“核对修改结果” | 同名文件更新，沿用同一会话。系统比较网关与租约参数的变化，再读取当前Ping收发统计，判断实验目标是否满足。 |
| 2:15–2:40 | 查看材料对比、Ping统计与排查进度 | 复测结果来自新提交的输出。页面显示这轮修改和检查结果，便于说明“修改了哪里、怎么确认”。 |
| 2:40–3:00 | 在追问框输入“为什么修改地址池后还需要重新获取租约？用一句话回答。”，按Enter发送；保存报告 | 完成后仍能追问原理；整个材料、引用、工具调用和交流过程可以保存为实验报告。 |

## 演示前准备

1. 按README启动服务，确认模型可用。使用在线测试站时提前访问一次，等待服务就绪。
2. 点击“新的排查”，保持演示会话独立。需要截图时可暂停背景动效。
3. 演示过程中按钮会显示等待状态；收到回复后再进行下一步。模型请求失败时保留材料，按页面提示重试。
4. 刷新带会话编号的地址可以恢复材料与分析。更新示例后再次打开“定位原文”，应定位到当前分析引用的行。
5. 报告和截图分别保存在项目内的runtime/exports和runtime/demo；在线报告由浏览器下载。
