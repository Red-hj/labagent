# LabAgent 开始使用与三人联调

当前版本可用于三人并行开发。黄泓钧推进模型和平台接入，付雨航验证网络实验和准备案例，赵亦康改进界面与演示。先用三天完成一次联调，再按比赛截止时间安排后续阶段。

## 每个人先在自己的电脑上运行

将协作包解压到自己的项目目录，使用 Python 3.10 或更高版本，双击 LabAgent 文件夹内的 start.cmd。保持启动窗口开启，在浏览器访问 http://127.0.0.1:8765 。这是各自电脑上的地址，队友不能用它直接访问黄泓钧的电脑。

当前 v0.4 已完成 LangGraph 暂停恢复、原始命令解析、路由核对、资料导入检索、报告生成与 DeepSeek 真实工具调用验证。队友解压后先运行 setup.cmd 安装依赖，再运行 start.cmd。未安装依赖时显示兼容模式，不能作为 LangGraph 集成验收。协作包不含模型密钥，队友需要自行配置 .env；未配置不影响本地规划与诊断。设备自动采集和 AgentArts 平台部署仍待后续接入。

## 第一次使用

1. 选择案例 01，点击“载入”，再点击“开始诊断 / 再次复测”。应发现区域不匹配，并指出 R2 违反实验要求。
2. 把提示等级切换到二级，再次诊断，查看设备、配置行号和相关原文。
3. 在 R2 配置框内将 area 1 改为 area 0，再次诊断。应进入“配置检查通过 · 待运行复测”。
4. 没有仿真环境时，可以在此结束本次配置体验。单独载入案例 03 可体验预置演示观测通过的界面；加载新案例会新建会话。
5. 有实际实验环境时，依据“实验环境与复测.md”采集邻居状态和端到端 Ping，填写运行观测，确认针对当前配置采集，再绑定配置指纹并复测。
6. 点击“保存记录到项目”。会话保存在 runtime/sessions.sqlite3，导出文件位于 runtime/exports。

“绑定当前配置指纹”只将所填观测与当前输入对应，不采集设备数据，不执行 Ping。“待运行复测”是正常中间状态，不是程序出错。

资源尚未到位时，记录缺少哪项资源和已完成的步骤；其他两位继续本地任务。不得将模拟响应、预置观测标记为平台或设备实际运行结果。

## 联调验收

先体验新增“R1—R2—R3”演示：按“载入下一阶段演示输入”推进三个阶段，核对区域故障、路由缺失、复测通过以及同会话报告。这些是合成数据，付雨航需要用真实实验替换验证。已有共享工作流无需队友重复搭建。

使用付雨航提供的一份配置：界面提交后，出现真实检查证据；提高提示等级后保留同一会话；修改配置后旧的运行观测不能直接让新配置通过；缺少运行结果时明确提示补充；提交新的实际观测后重新核对；最终导出一份会话记录。

另验两种情况：配置缺失时显示“需要补充信息”；模型不可用时本地检查仍可使用。单纯把页面上的文字改成“成功”不构成验收。

## 协作约定

- 引擎和接口由黄泓钧统一维护；第一轮保持 docs/接口说明.md 中现有字段和状态含义。
- 付雨航主要交付 data/team_cases、data/course_notes 下的案例、原始证据和教学资料；不要将所有新测试直接追加到已有 16 个回归案例目录。现有部分测试按 16 个样例验收，需要扩展时一起调整。
- 赵亦康先修改 web 下的界面；如需改用 Streamlit，先与黄泓钧确认接口与目录安排。跨源访问当前受限制，默认使用同一服务提供的网页。
- 每次交付附上修改的文件、验证步骤和未解决问题；合入前保留双方副本，避免用整个文件夹覆盖另一位的成果。
- 用协作包或后续建立的共享代码仓库交换源码。模型密钥由各自配置，不在协作包里分发 .env 和运行数据库。

具体职责见同目录下三份个人任务书。对外提交前另确认学校内部截止时间和比赛材料要求。
