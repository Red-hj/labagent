# 赵亦康 界面与演示任务书

当前v0.10已完成首页交互、两阶段示例载入、原文定位与工具记录。三分钟演示脚本和比赛讲解结构见[docs/demo/三分钟演示.md](../demo/三分钟演示.md)。后续重点是替换真实案例、正式PPT与录屏，按[GitHub Issues](https://github.com/Red-hj/labagent/issues)中的对应任务继续；下方早期任务作为历史参考。

v0.3 已有资料导入、试查、范围选择与原文定位界面，无需重复搭建。下一步重点验证用户能否分清实验要求、检索参考和实际运行证据，并完善资料导入及引用查看体验。保留版本、行号和历史报告引用。

本轮目标：基于已有本地网页和接口，让学生清楚完成配置提交、查看提示、修复和复测，并形成可演示的完整流程。

## 先阅读与启动

阅读 README.md 和 docs/接口说明.md。自己的电脑安装 Python 3.10 或更高版本后，双击 start.cmd，访问 http://127.0.0.1:8765 。无需等待模型或 AgentArts 资源到位。

已有网页位于 web/index.html、web/style.css、web/app.js，可在此基础上改进。当前页面通过同源 HTTP 接口连接引擎。改为其他框架前先与黄泓钧确认，避免额外的跨源或会话问题。

## 本轮工作

1. 跑通案例 01、02、03、10，理解发现故障、等待复测、预置观测通过、信息不足四种界面。
2. 检查输入、设备文件导入、原配置行号、提示等级和运行观测输入是否易懂。配置改变后要明确表示旧结果待更新。
3. 同一实验的提示升级和修改复测保留 session_id；载入新案例才新建会话。
4. 保留执行记录和知识来源，标明当前是本地规则模式。模型与平台实际接入后再显示相应状态。
5. 将付雨航交付的一个真实案例制作成约三分钟演示脚本：问题、证据、提示、学生修改、运行复测、学习记录。

## 交付物

修改后的 web 文件、docs/demo 下的演示脚本和复现步骤。截图及录屏放在项目内的 runtime/demo。交付时列出改动文件，不覆盖引擎和其他队友数据。

## 验收标准

- 能通过网页完成引擎调用，而非固定显示预设答案。
- 错误位置、证据与后端结果一致，接口失败有明确提示。
- 没有运行观测时显示“待复测”，不会显示网络已恢复。
- 配置改变后，旧观测不能让新配置直接通过。
- 保存记录功能写入本地项目文件夹。
- 案例 03 明确标识为预置演示，真实实验与演示素材的来源可区分。

先将交互和案例流程跑稳，再制作正式 PPT 和录屏。平台展示部分等待黄泓钧提供真实运行证据。
