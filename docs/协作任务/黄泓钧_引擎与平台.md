# 黄泓钧 引擎与平台任务书

v0.4 已完成 DeepSeek 真实模型调用、链路选择与证据工具回送，并通过合成数据的三阶段流程验证。接入记录见 docs/integration/DeepSeek接入与验收.md，后续主线见 docs/开发方案_v0.4.md：按假设主动收集运行证据 → 真实案例验证 → AgentArts 落地。当前模型规划只支持待检查链路选择，不应表述为任意工具自主诊断已全部完成。

本轮目标：理解并维护本地诊断流程，验证真实模型工具调用，并尽早完成 AgentArts 的一个模型节点与一个工具调用。已有本地规则和模拟测试可作为开发基础，实际平台能力需要登录后验证。

## 先阅读

按顺序阅读 README.md、docs/接口说明.md、labagent/engine.py、labagent/tools.py、labagent/agents.py。先理解输入输出和状态，再研究可选模型循环。当前实验类型由用户选择的 OSPF 场景与显式拓扑决定，没有实现通用多课程意图识别。

## 本轮工作

1. 在自己的电脑跑完案例 01 的故障与修复配置流程，解释 findings、unknowns、runtime_missing 三类结果。
2. 使用已授权的模型服务，在项目内 .env 配置完整地址、模型名、密钥。网页勾选后，确认 llm.tool_trace 有真实工具调用和返回；仅出现一段模型文字不代表工具调用成功。
3. 在 AgentArts 验证模型接入和最小工具包装。可复用 labagent.adapters.diagnose_ospf_tool 的边界；依据平台实际工具接入方式完成包装。现有 127.0.0.1 服务不能直接供云端访问。
4. 记录调用耗时、失败类型和回退状态，不输出密钥。有资源问题时写明缺少的权限或服务，继续处理本地联调问题。
5. 汇总队友提出的接口需求与诊断规则缺口，逐项处理，保持状态含义一致。

## 交付物

在 docs/integration 下整理接入说明，在 runtime 下保留本地验证结果。实际模型或平台的演示截图、脱敏日志需注明来源与测试时间。核心实现仍放在 labagent，相关行为变更应配套验证。

## 验收标准

- 模型接入成功时，至少一次实际只读工具调用可追踪，工具结果能回送模型。
- 模型超时或不可用时，本地检查仍返回结果。
- AgentArts 有资源时，演示一个实际平台调用；没有资源时明确列出已完成代码和待验证步骤。
- 能通过现有本地测试，与队友完成一条共同实验流程。

第一轮后再决定诊断和教学如何在平台分工。暂不扩大到 Linux、数据库、自动写设备配置等方向。
