v0.7.2将功能说明统一为正面描述：支持什么、需要哪些材料、下一步怎样操作。清理工具描述和工具返回中的固定能力排除说明，README同步采用相同表达。使用现有合成材料真实追问“第一次使用时提供什么材料、怎么开始”，回复直接列出材料和使用步骤。

v0.7.1移除老师、助教人格和固定的“未验证”式结尾。正文先回答当前问题，再说明关键参数和操作；引用行号留在展开区。当前追问单独放在模型的最新用户消息中，避免被初始诊断问题覆盖。材料导入显示添加/更新反馈；提交时诊断区显示等待时间，追问立即进入对话并显示等待气泡，完成或失败都有提示，失败保留输入。

v0.7将入口补成同会话交互：追问原因、获取修改步骤、直接在采集请求下粘贴材料、实际比较前后差异并核对Ping包数。实验目标对应的提交观测通过后结束本轮，概念追问继续保留上下文。报告是过程存档。

页面移除了大标题，蓝白工作区直接承接材料与对话。背景独立在ambient-network.js，按用户指定原站的公开配置使用本地tsParticles 3.9.1：push每次4个节点、grab距离400、parallax force60/smooth10、move speed2、普通连线150px；不再使用自制排斥力。库及许可证位于web/vendor。

v0.6 默认入口改为“提供材料 → 助教分析 → 按提示补充”。用户可上传或粘贴文本材料，问题描述选填；模式、模型开关、拓扑JSON与绑定操作从首页移出。原专业界面保留在 /workbench 供队友开发。

v0.5 保留 OSPF 专用检查，同时新增开放网络排查。开放模式不采用故障类型枚举：模型根据问题自主选择材料读取和知识检索，提交有原文引用的假设，并请求补充证据；LangGraph 保存状态，下一次同会话输入恢复后依据新材料继续分析。

材料以文本为入口，不要求先被 VRP 解析器识别。工具为 read_source、retrieve_reference、compare_materials、check_submitted_pings、submit_hypotheses；分别完成读取原始材料、检索参考、比较前后材料、核对上传Ping统计、提交分析。引用使用材料编号与行号，本轮读过且逐字匹配即可，不额外维护指纹。运行输出继续复用已有配置绑定机制，避免误用旧观测。

模型结论由原文依据、推断和补充请求组成。开放模式当前负责分析与继续取证，OSPF 工具负责已支持范围的确定性检查。后续增加验证工具时，直接接在现有流程上，不必把所有知识编码成故障规则。
