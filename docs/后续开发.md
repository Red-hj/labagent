### 功能深度与下一步

当前核心是“实验目标→主动选检查→获取新观测→核对修改结果”的持续排查流程。技术工作围绕三项实用能力推进：保留跨轮实验状态与证据来源；按候选原因的区分能力和采集成本选择下一项检查；把修改前后观测、目标完成情况与建议关联起来。现有工具规划、目标核对和修复对照已提供基础。下一步优先真实 eNSP 案例联调与可恢复的实验状态摘要，再据使用记录改进检查选择；创新效果通过真实案例的操作数量、判断依据与复测结果体现。

### 实施边界与具体落点

- 执行层负责模型调用、工具循环、每轮状态和检查点；实验层继续负责原文引用、设备观测、实验目标、提示级别、报告与账号范围。React 负责展示和交互，不在浏览器内决定实验是否达标。
- 第一阶段建议从现有 `session_id → attempt → tool_call_id` 对应关系开始，不再建立另一套业务历史或日志库。进度流可继续使用 NDJSON；新的事件增加稳定标识与结构化状态，不需要为参考 Codex 而改用 JSON-RPC 或 WebSocket。
- 当前网站通过 AgentArts 执行诊断，浏览器手动采集实验电脑输出后再交给诊断。让云端模型主动调用学生电脑工具，需要网站转发、当前账号绑定和云端工具回传的明确通道；仅迁移 React 或让云端访问 `localhost` 无法打通这段链路。
- 同一轮工具可以有执行成功、执行失败和结果未送达等情况；实验目标的 `passed/failed/needs_evidence` 单独保留。一次工具成功只表示得到输出，不表示实验完成。
- React 迁移前向共同页面维护者说明入口、组件范围及兼容期；事件、任务取消及工具回传变更前说明接口范围。先以分支 PR 验证，沿用现有部署与账号数据。
- 多智能体留待出现可独立评测的子任务时再引入。当前先把单个智能体的证据、状态和恢复做好；直接接入 Codex / Claude Agent SDK 另做模型兼容、部署与费用评估，当前实现沿用已有模型与运行时。

用 DeepSeek Flash 非思考模式在 6 个公开快照上跑 3 组，共 18 轮有回答。材料为 4 组合成 VRP 配置/输出与 2 组隔离 FRRouting 实采摘录。每组用相同题目、输入和单次最多 1,600 生成 token。直接问答一次读全材料；基础工具组与完整工具组都至多 6 次模型请求，区别为是否提供实验目标检查和主动检查选择。两个补证快照独立重跑，只替换 R3 配置摘录为同一状态的完整配置，以隔离新增材料的作用。

| 人工核对项 | 直接问答 | 基础工具 | 完整工具 |
| --- | --- | --- | --- |
| 达标结论正确 | 6/6 | 6/6 | 6/6 |
| 可定位案例包含全部预期问题 | 3/3 | 3/3 | 3/3 |
| 严格通过 | 1/6 | 5/6 | 4/6 |
| 健康案例建议额外补证 | 2/2 | 0/2 | 0/2 |
| 模型请求／输入输出 token 合计 | 6／8,881 | 18／101,603 | 20／150,269 |
| 单例耗时中位数 | 4.75 s | 7.35 s | 8.67 s |

严格通过按对学生展示的正文、步骤和补证判断，要求达标判断、问题定位、补证和最小修改同时符合预期。结构化目标单独核对。修改之后重新验证不计为额外补证。三组均识别“Ping 通但实际走静态路由”不符合 OSPF 要求，也均在只见 R3 配置摘录时过早认定 R3 漏配。直接问答另有一次先删唯一生效的静态路由、再补 OSPF，一次未确认 R2 LAN 资料就推断未宣告；完整工具组在材料足以定位后仍重复索取当前路由表。完整组 6/6 调用了实验目标检查，0/6 选择了主动检查工具；另有 1 次把“两个 transit 接口在 Area 0”提取成“R1 存在 transit 接口”并判通过，虽正文判断正确，结构化证明仍不完整。

小样本用于定位产品问题，未执行模型修改建议，不能据此计算实际修复成功率或给三种方案定优劣。

公开案例与评分判据在脚本内。省略 `--execute` 可先查看调用上限（全批最多 78 次）。运行输入、调用记录、逐题答案和人工核对记录保存在本地。

```powershell
python -X utf8 scripts/evaluate_diagnostic_workflow.py --execute --env-file .env --output runtime/b-diagnostic-workflow
```

### v0.19.5 证据核对回归

- 读取设备配置时分别显示快照范围和已读范围。明确标为摘录的材料即使包含 `return`，也不能证明某命令不存在。
- 对明确写出设备、接口和区号的要求逐台检查。使用 FRRouting 实采修复前后材料，R1/R2 区域检查分别为通过/失败 → 通过/通过；缺一端或只看到其它接口的区域时仍待补证。用同一行要求替换成“接口存在”的旧模型提交也不能绕过此核对。
- 用 DeepSeek Flash 对 4 个快照、2 种工具模式实测 8 轮。完整模式正确列出 FRRouting 两端区域的结构化结果，并拦下一次只凭拓扑添加接口的目标。只给 R3 摘录时，两种模式的最终回复仍提前指认漏配（同时索要完整配置）；补齐后两组都能正确定位。另有一次完整模式在 FRRouting 故障例中把管理距离 200 与 110 的优先级说反，并要求删除允许的备份路由。配置摘录的自由文字抢判仍未通过；备用路由误删的实测修复见下段。
- 对明确允许保留备份、Ping 已通、R1 已安装静态路由且另一端区域不匹配的 FRRouting 实验，依据这四项检查生成改法，保留备份。重新采集同一轮故障与修复输出：只改 R2 transit 区域，R1 配置不变，两端静态路由留在配置中；生效路由双端由静态切换到 OSPF，双向 Ping 各 5/5，七项检查从 3/7 恢复到 7/7。最终版 DeepSeek Flash 在新采两阶段分别给出和已执行操作一致的修复、以及无需修改的达标结论；明确禁止静态路由的合成 VRP 对照未套用保留建议。这里验证了一条实际修复，尚不统计整体修复成功率。
- 基于 v0.19.6 复测配置摘录：对明确要求 OSPF 的目标，只有目的设备 Loopback 摘录、现有 Ping 已失败，且缺少对应接口运行证据时，按已上传的 Ping 原文说明现象，仅索要目的设备缺失的 OSPF 证据，不给未经确认的配置改法。跑了两种工具模式各 2 轮：摘录时 2/2 只向 R3 补证，完整配置时 2/2 正常定位 R3 并给出调整建议。完整配置的一轮仍额外询问当前路由表，新对照见下方 v0.19.7 记录。此结论针对有原文标记的 VRP Loopback 摘录，未覆盖所有缺资料场景。
- 基于 v0.19.7 分开处理 VRP「已证明无匹配路由」和「表不足」。给既有两个合成故障快照补上公用表范围和行数元数据做专项对照，原 6 例基线保持不变。DeepSeek Flash 两种工具模式 4 轮均未重复索要已核对的当前表；配置摘录仍只向 R3 补证。完整配置两轮均定位 Loopback 未加入 OSPF，其中完整工具组另提出了不必要的反掩码改动，未计为修复建议通过。此轮未执行 VRP 修复。

  复跑：`python -X utf8 scripts/evaluate_diagnostic_workflow.py --execute --env-file .env --output runtime/b-vrp-full-table --complete-vrp-table --mode tools --mode goals --case vrp-partial --case vrp-supplemented`。
- 独立题集复核、实机采集、录屏和修复成功率的剩余交付见[付雨航验收清单](协作任务/付雨航_实验数据与评测.md)。

## B 组 OSPF 诊断训练数据

`ospf-diagnosis-sft-seed-1` 提供 30 条训练样本和 10 条验证样本。均为 LabAgent 新生成的六路由器 VRP 风格案例。训练使用链形、分支和环形，验证使用梯形。训练样本含 15 条故障、6 条静态正常、9 条资料不足。覆盖区域冲突、两端区域相同但违反实验要求、接口关闭、network 匹配错误、子网不一致，以及缺设备、接口或地址证据。正常样本含合法的多区域链路。

每行是 `messages` JSONL。输入包含拓扑、地址规划和配置，目标包含状态、故障码、链路、设备、可逐行核对的原文和下一步。标签按已知变更预先定义，由现有规则核对，40 条都通过静态检查及恢复基线验证。训练与验证按拓扑分组。已对照独立 60 例的配置指纹及拓扑度序列，两者均无重复。24 道检索题继续用于单独评测。样本用于启动监督微调试验，当前阶段完成的是数据生成和核对，暂无训练后模型权重。

```powershell
python -X utf8 scripts/prepare_ospf_training.py runtime/ospf-training-seed
```

本地有 B 组 60 例评测输入时，追加 `--holdout-inputs data/b_benchmark/inputs` 可同时复核分离情况。输出目录含 `train.jsonl`、`validation.jsonl` 与 `manifest.json`。

本轮同步核验了公开补充来源。外部数据独立保存，当前训练包使用项目新生成的 VRP 样本。

- Cisco CML 沙箱快照提供同一互联接口关闭前、关闭后、恢复三阶段证据。本地核对到 Full 邻居设备数为 2 → 0 → 2，并提取仅含接口关键信息的候选数据。来源仓库为 MIT 许可，设备语法为 IOS XE。[固定快照](https://github.com/Bryancruzcb/network-change-validator/tree/e5396271fca319e0e2e53e23d9acabacd709c491/fixtures/lab-2026-09-12/ospf)
- NetAgentBench 的两份 Apache-2.0 六节点 FRRouting 任务包含拓扑和正确配置意图，可用于构造配置样本。诊断样本需再增加故障配置、定位标签和运行证据。[固定任务目录](https://github.com/twabi/NetAgentBench/tree/a65080674f4ce259409b47b057a347efc6a5ca09/benchmark-tasks/platforms/frr/ospf_configuration/tasks)
- Cornetto 有 231 个修复评测场景，公开数据保留故障配置与验收条件，除一个示例外未发布正确配置与故障标注，适合后续做外部修复评测。[Cornetto 数据说明](https://github.com/nsg-ethz/cornetto#dataset)
