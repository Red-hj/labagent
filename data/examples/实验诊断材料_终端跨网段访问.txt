实验诊断材料：终端跨网段访问
说明：以下为合成教学材料，用于体验诊断流程。

一、实验目标与现象
PC1通过DHCP获取地址，并通过R1访问服务器SRV1的10.30.0.10。
PC1已经获取地址，但访问10.30.0.10失败。
本实验规定PC1所在网段的网关为R1的10.20.0.1，没有其他网关或VRRP设备。

二、拓扑与设备
PC1 -- SW1（二层交换）-- R1的GE0/0/0
R1的GE0/0/1 -- SRV1
SW1连接PC1和R1的端口均为VLAN20的接入口，端口状态均为UP。
SRV1地址为10.30.0.10/24，默认网关为10.30.0.1。

三、R1相关配置节选
dhcp enable
interface GigabitEthernet0/0/0
 ip address 10.20.0.1 255.255.255.0
 undo shutdown
 dhcp select global
#
interface GigabitEthernet0/0/1
 ip address 10.30.0.1 255.255.255.0
 undo shutdown
#
ip pool VLAN20
 network 10.20.0.0 mask 255.255.255.0
 gateway-list 10.20.0.254
 dns-list 1.1.1.1
#

四、PC1当前地址信息
IPv4 Address: 10.20.0.10
Subnet Mask: 255.255.255.0
Default Gateway: 10.20.0.254
DHCP Enabled: Yes

五、本轮运行记录
PC1执行ping 10.20.0.1：发送4个，收到4个。
PC1执行ping 10.20.0.254：发送4个，收到0个。
PC1执行ping 10.30.0.10：发送4个，收到0个。
PC1的ARP表：10.20.0.1有对应MAC；10.20.0.254状态为Incomplete。
R1执行ping 10.20.0.10：发送4个，收到4个。
R1执行ping 10.30.0.10：发送4个，收到4个。
SRV1执行ping 10.30.0.1：发送4个，收到4个。
R1路由表包含10.20.0.0/24和10.30.0.0/24两条直连路由。

六、待诊断的问题
请根据以上材料解释PC1无法跨网段访问的原因，指出材料依据，给出修改建议与修改后的验证步骤。
